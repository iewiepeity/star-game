## 2. 五年的連續主題

玩家起點是大學畢業後的成年人，既有引擎以 22 歲起算；職業、作品、名氣、經紀公司與伴侶由遊戲經歷形成。五年共 260 週，年度章節從第 1、53、105、157、209 週展開。

| 年度 | 章節重心 | 與後續的連接 |
| --- | --- | --- |
| 第一年：活下來 | 房租、零工、課程與休息如何共存 | 空白履歷可以維持空白；第二年回看玩家真正選擇的起步方式 |
| 第二年：我是誰 | 為一段時間選定職涯方向 | 專注方向影響可接工作的既有條件，文本交代投入與暫時放下的機會 |
| 第三年：位置有限 | 正面競爭、合作聯盟或獨特定位 | 不同方針留下不同聲勢、評價與限制；後續回響延續各自代價 |
| 第四年：選擇有代價 | 商業資源、創作自主或可持續作息 | 條件不只停在宣言，對接既有收入、工作限制與並行合約規則 |
| 第五年：留下什麼 | 代表作、關係、傳承或整合生活 | 年度目標是選擇方向；結局仍按實際成果判定，不把願望當成已完成 |

終局不只服務成功玩家。沒有代表作時承認仍在起步；普通作品有其完成過程；自由身不被寫成公司安排；沒有戀人時不補入伴侶。提早退圈依真正週數收束，死亡有獨立的未竟尾聲。疲勞、關係信任或經紀狀態有資料時才補入正文，舊快照缺少欄位時不推定玩家必然疲憊或沒有公司。

## 4. 養成、娛樂圈工作與趣味

工作文本按真正的工作環節推進：試鏡通過只是取得合作機會，正式製作才處理排練、素材、收音、連戲、剪接與交付；完成不等於大賣。75 份通告各有具體題材與現場問題，旗艦案再把方法選擇接進既有重要節點。原創作品則把歌曲、劇本、節目拆成不同工藝問題，發行反應依實際 `marketScore` 選擇；續作依 `quality` 分檔，避免把市場聲量和製作品質混為同一件事。

養成不以勤奮自動換取完美結果。玩家會遇到預算、時段、曝光範圍、準備時間與身體負荷的拉扯；有人能保住作品的核心，卻得接受縮小規模，有人先換到曝光，後續仍要補做協調。日常趣味來自口誤、便當、道具標籤、版本命名與職業習慣，讓人物在工作之外仍像會疲倦、會開玩笑的人。

| 旗艦製作版本 | 製作中途直接確認，先保存選擇才繼續工作 | 不受每週事件佇列延遲；品質與成品記錄採用真正的選擇 |
| 原創與續作完成 | 按實際市場／品質結果與議價狀態選文 | 反應普通時不借用爆紅段落，接受加價後不再誤寫原報酬 |

分支交稿採「前提 → 選擇 → 代價 → 延遲 → 回收」規格。沒有延遲事件的生活小事，結果就停在當下，不用「下週一定有人來找你」暗示未接入的後續。完整維護規則與已使用的資料入口見 [編輯總綱](EDITORIAL-GUIDE.md)。

## 8. 原文備查與查驗指令

備查以指定基準 commit 為準，不依賴人工另抄片段。新稿和原文都可逐檔定位：

| 檔案 | 用途 |
| --- | --- |
| [REPLACEMENT-INDEX.md](REPLACEMENT-INDEX.md) | 可直接閱讀的逐檔替換表，列出來源、前後原始碼漢字數、原因及完整原文／差異查閱入口 |
| [manifest.json](manifest.json) | 所有變更來源檔案的新增／替換類型、替換理由、前後 SHA-256、原始碼漢字數及基準 SHA |
| [originals.json.gz](originals.json.gz) | 被替換來源的完整原文，以原路徑為鍵；新增檔案沒有虛構的舊稿 |
| [source-changes.patch.gz](source-changes.patch.gz) | 相對基準的完整 `src` 差異，包含已納入 Git 的新增來源 |
| [audit-narrative-rewrite.mjs](../../../scripts/audit-narrative-rewrite.mjs) | 驗證封存與差異內容的雜湊，並比對每個變更來源的當前內容；也可讀取單檔原文或完整差異 |
| [EDITORIAL-GUIDE.md](EDITORIAL-GUIDE.md) | 後續改稿用的五年主題、人物聲音、分支規格、像素尺度、相容規則及詳細來源表 |

在儲存庫根目錄執行以下指令。一般查驗不會改寫封存：

```bash
node scripts/audit-narrative-rewrite.mjs
node scripts/audit-narrative-rewrite.mjs --original src/data/location-events.js
node scripts/audit-narrative-rewrite.mjs --diff
```

第一行檢查封存、差異及目前來源是否與清單一致；第二行輸出指定來源的完整舊稿；第三行輸出完整差異。雜湊驗證確認資料一致，不能取代劇情品質或遊戲流程驗證。

僅在維護者有意重新製作本次替換紀錄時，才使用寫入模式。新增 `src` 檔案必須先納入 Git 暫存區，讓差異檔包含新增全文；此指令會覆寫本目錄的清單、原文封存、差異檔與可讀替換索引，日常審閱無須執行：

```bash
node scripts/audit-narrative-rewrite.mjs --write
```

遊戲整體檢查入口為：

```bash
npm run check
```

這會依 `package.json` 執行格式、靜態檢查、內容驗證、單元測試、模擬、資產／PWA 檢查與建置；瀏覽器測試是另外的檢查流程，不包含在此指令中。
