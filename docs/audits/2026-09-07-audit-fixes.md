# 像素唯一版本：修復前後差異分析

日期：2026-09-07。修復前：main `05a792c`，核心 1.41.1／Pixel 0.18.1。修復後：核心 1.41.2／Pixel 0.18.2。

## 修復結果與玩家感受

本次逐項處理原報告的十個問題。影響最大的變更是存檔：從 localStorage 的整份資料與多份備份，改成 IndexedDB 原子交易，並補齊損毀復原、寫入失敗回報、多分頁衝突及立即重整的保護。玩法、既有作品、人物關係和五年紀錄延續使用。

| 原問題 | 修復前 | 修復後 | 驗證依據 |
|---|---|---|---|

## 長期容量：同一份資料的直接比較

使用原檢視留下的第 53、105、157、209、261 週資料，逐一在新 Chromium 儲存空間測試。測試順序維持「自動兩次、位置 1 兩次、位置 2–5 各一次」，共八次寫入。修復後額外塞入 480 萬字元的其他 localStorage 資料，確認遊戲槽位不再與該容量共用。

| 週數 | 單份 JSON 大小 | 修復前成功寫入 | 修復後成功寫入 | 歷史完整性 |
|---|---:|---:|---:|---|
| 53 | 585,256 bytes | 8／8 | 8／8 | 五槽 history 與輸入資料相同 |
| 105 | 1,089,975 bytes | 7／8 | 8／8 | 相同 |
| 157 | 1,585,150 bytes | 5／8 | 8／8 | 相同 |
| 209 | 2,090,678 bytes | 3／8 | 8／8 | 相同 |
| 261 | 2,602,644 bytes | 3／8 | 8／8 | 相同 |

另一個固定種子五年測試使用遊戲實際邏輯推進 260 週，再對自動槽與五個手動槽各寫兩次，並驗證搬移備份、刪除、復原及重新開啟資料庫後的結局。此測試不刪掉人物或歷史來減少資料量。

差異的原因是儲存架構，不是擴大 localStorage 配額。IndexedDB 有自己的容量管理；實際可用空間仍依裝置及瀏覽器決定，測試結果不能解讀為無限容量。

## 資料可靠性的具體改變

### 原子保存及舊檔遷移

寫入主檔、覆寫前備份與 revision 在同一筆 IndexedDB 交易內完成，任一步失敗就不提交。畫面讀取的快取也只在交易成功後更新，避免「資料庫失敗但選單已顯示成功」。

首次遷移涵蓋舊像素自動檔、五個手動槽、覆寫備份、刪除復原和搬移備份。只有資料庫成功提交，而且舊值仍與已遷移值完全相同時，才移除該 localStorage 值；不碰其他遊戲、偏好或舊版相容存檔。後續啟動以資料庫為準，不會讓重複出現的舊鍵值覆蓋新進度。

### 損毀與多分頁

讀取失敗不再默默開新人並持續覆寫。復原須由玩家選擇；損毀原始字串隔離保存，仍有下載入口。多分頁以交易中的版本比較為最終判定，通知頻道只是用來及時顯示衝突，不是唯一的防護。

### 立即重新整理與更新

完整回歸發現，非同步寫入可能來不及在卸載前完成，因此補上一份「每分頁離開前暫存快照」。它僅在隱藏或離開頁面時同步暫存；啟動時比對原 revision、寫入者與序號，安全才接續，否則保留在存檔選單供玩家預覽，不覆蓋最新進度。正常交易完成後會清除較舊暫存。

新版畫面「已儲存」代表等待中的 checkpoint 已完成。讀檔／新周目切換期間會暫停世界；另一分頁先更新時，先處理進度衝突，再回到保存與更新確認。

離開頁面暫存仍是備援機制：localStorage 完全不可用或已滿、瀏覽器沒有送出離開事件、作業系統直接終止程序時，未提交的瞬間變更不能保證復原。先前已提交的資料仍保留，可用 JSON 匯出作額外備份。

依據：[storage.js](https://github.com/iewiepeity/star-game/blob/main/src/pixel/storage.js)、[主流程](https://github.com/iewiepeity/star-game/blob/main/src/pixel/main.js)。

## UI 與閱讀差異

- 原始檢視的 20 個配色／頁面組合，修復後 axe 所檢查的違規為零；另加入「實際切換五種配色後」的檢查。過場動畫結束後取樣，避免將轉場中的暫態顏色算成固定文字對比。
- 四種尺寸的 78 個基礎畫面沒有水平溢出或 JavaScript pageerror；另完成 16 個居家、城市、關係、劇情和結局畫面巡檢。
- 手機週表改成較寬的日卡，增加垂直閱讀長度，以換取完整活動名與可讀標籤。所有天數仍可選擇，沒有減少排程功能。
- 能力狀態改成有間距的四格；創作的名稱和數值使用正確定義列表。
- 結局保存／作品／新人生按鈕移到長篇回顧之前，回顧分段；城市日曆主畫面保留赴約的日期成本，特殊生日算法收進說明，並調整缺少舊日期的文字。
- 手帳、首頁及職涯的多個入口保留作為快捷方式；未刪減功能或重排整個資訊架構。

無障礙自動工具只能涵蓋部分問題；部分背景／圖像上的對比和屬性仍被列為需人工判讀（incomplete），不等同通過。這裡報告的是指定組合與規則的已確認違規結果，不是完整實機讀屏認證。

## 驗證結果

- `npm run check` 通過：500 個單元測試，加上格式、lint、資料／內容、五年模擬、世界回應、資產、PWA 及發布建置。
- 原報告五組里程碑共 40 次指定寫入全部成功；五個手動槽的 history 與原始輸入相同。另設實際模擬 260 週的全槽覆寫、刪除復原和重開測試。
- 78 個四尺寸基礎畫面、16 個進階畫面未發現水平溢出或 pageerror；20 個指定配色／頁面組合沒有已確認的 axe 違規。
- 新增 10 個儲存單元案例、8 個跨瀏覽器案例；另以既有故事、立即重整、更新與完整離線流程回歸非同步儲存整合。
- 瀏覽器矩陣為桌機／手機／平板 Chromium、手機／平板 WebKit、Firefox。發布以 [CI 的核心與 12 個 E2E 分片](https://github.com/iewiepeity/star-game/actions/workflows/ci.yml)全部成功為合併條件，實際 run 與 commit 記錄於發布 PR。

本機高並行回歸也揭露測試本身需要調整：五年資料生成與瀏覽器寫入分開計時；直接切換章節的 fixture 若遇到上一幕尚在提交，僅對明確 revision 衝突重新讀取後重試。正式遊戲仍維持衝突暫停，由玩家決定是否接續，不使用測試的自動重試方式。

## 後續維護重點

1. 保存、讀檔、新周目與更新的成功狀態必須等待交易完成；不要把 Promise 當成布林成功值。
2. 測試故事中段時應建立正確 IndexedDB fixture；舊 localStorage 鍵只用於遷移案例，不能拿來覆蓋新版資料庫。
3. 新增會重建畫面的搜尋功能時，必須保留 composition 組字期間的 input 節點。
4. 新文字樣式應沿用主題色與閱讀倍率；檢查窄螢幕和大字，不只看桌面預設配色。

[完整功能、可執行行為與限制](2026-09-07-feature-guide.md)另以玩家操作與系統深度整理，沒有把尚未實作的項目列為已完成。
