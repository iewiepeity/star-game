## 已修正問題

| # | 問題與觸發方式 | 修正結果 |
|---|---|---|
| 1 | 公開→地下→再次公開戀情，每次都增加粉絲與話題度 | 每位人物的首次公開獎勵使用既有事件旗標去重，重載後仍有效 |
| 2 | 嚴重失和由關係引擎自動分手，仍保留公開戀情狀態 | 所有退出關係的轉換統一清除公開狀態；公開分手的話題效果集中結算 |
| 3 | `matchesConditions` 傳入另一份遊戲狀態，能力／服裝卻讀全域核心 | 有效能力與服裝加成使用傳入的存檔 |
| 4 | 職涯路線條件也錯用全域存檔 | 職涯路線計算接受明確的遊戲狀態 |
| 5 | 隱藏能力為 0 時加 1，錯把 0 當缺值並跳到 501 | 僅缺值才補預設 500；真正的 0 正常增減 |
| 6 | 直接重播已結算事件，仍可重複給獎與新增紀錄 | 事件 ID 已存在歷史時拒絕再次結算 |
| 7 | 全部選項因條件鎖定時，被當成無選項事件而結算 | 保留待選擇狀態，不套用獎勵或寫入歷史 |
| 8 | 人物／部分職涯行程以無效選項呼叫結算，默認採用第一個回答 | 原版個人行程與像素版職涯結算先確認有效選項；重載仍需玩家選擇 |
| 9 | 邀約後失和而互動失敗，仍標記活動／NPC 檔期完成 | 保留失敗結果，活動標記 failed、釋放檔期，不計入週目標；嘗試當天仍占一天 |
| 10 | 像素版快捷社群、快捷創作沒有 scheduled task，完成後漏算週目標 | 日結算記錄實際 taskKind，由共同的週目標引擎計數；排程預覽也投影快捷行程類型，不先給獎 |
| 11 | 社群／論壇以原型屬性名稱作回覆類型，誤認為有效選項 | 僅接受選項表自身存在的鍵 |
| 12 | 先預約製作日，再變更團隊，造成新人物未預約／舊人物空占檔期 | 待執行的製作預約存在時，須先取消再改團隊；失和人物仍可移出但不能重新邀入 |
| 13 | 週中簽約時共演預約排到已過去的日子 | 排除已結算日期；整理舊預約時釋放過去空檔並尋找未來共同檔期 |
| 14 | 海外行程直接呼叫可只付剩餘現金，業界評價也可能超上限 | 核心結算要求完整 $5,000，拒絕無效選擇，聲望最高 1,000 |
| 15 | 戀愛轉換只檢查階段順序，未在結算檢查心意、信任與週數 | 共用 romanceOpportunity 在實際推進時再次驗證 |
| 16 | 已排入的告白／承諾談話失去資格後，仍顯示成功與給關係獎勵 | 接受選項依當前狀態重新判定，失效選項不結算，保留其他可用回應 |

新增 `tests/comprehensive-gameplay-audit.test.mjs` 共 17 組回歸案例；另新增戀情切換、重載保存及獎勵去重的實際瀏覽器案例。3 處舊測試設定改用真實可選答案／達標的好感值，避免依賴已移除的默認成功行為。

## 適用範圍

社交系統是單機遊戲內的 NPC／論壇模擬，本次檢修沿用既有設計。瀏覽器測試為自動化桌機／行動裝置模擬，並非實體手機真人盲測；五年測試為可重現模擬，不等同逐段人工讀完所有隨機分支。正式站台需合併並通過專案發布流程後才會更新。
