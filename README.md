# 星途未定

目前發行候選版本：**v1.29.0 Beta**。正式頁面只部署通過 Core 與桌機／手機 E2E 的 commit；版本紀錄、發布流程與真人盲測規格見 [`CHANGELOG.md`](./CHANGELOG.md)、[`RELEASE.md`](./RELEASE.md)、[`BETA-PLAYTEST.md`](./BETA-PLAYTEST.md)。

純規則版繁體中文娛樂圈五年成長模擬遊戲。玩家從新人租屋處出發，自訂角色、訓練能力、投遞經紀公司、參加試鏡、完成作品、經營人際與戀愛、面對輿論與市場，最後依五年留下的作品、獎項、關係、財產與公眾位置進入結算。遊戲不需要 AI／API Key，也不需要登入；GitHub Pages 開啟後即可在瀏覽器單機遊玩。

## 行程加速（v1.29.0）

- 行程與設定頁提供手動、1×、2×、4×、8×、16×；一般結算分別停留 4、2、1、0.5、0.25 秒，過場同步加速。
- 過場中可即時切換或暫停；暫停後調整倍速不會自行恢復，手動模式仍由玩家進入下一天。
- 選擇、人物劇情、現場看板與週總結保留確認，不因倍速跳過。速度選擇保存在本機，更新與讀檔後沿用。

## 清爽地圖與自由創作（v1.28.0）

- 城市原畫減少密集房屋、樹木與裝飾，保留暖色水彩和全部 26 個互動地點。
- 地點介紹改為純文字卡，首頁移除物件懸停外框；鍵盤焦點留在名稱標籤。
- 行程與創作卡片給圖片獨立欄位，避免圖片蓋住文字，大字模式同步適配。
- 同一作品可在同週安排多天創作／製作，每次仍占一天；提前完成後多餘行程轉為休息。
- 取消單日製作只釋放當天合作檔期，製作預算仍只扣一次；投稿與發行保留重複排程保護。

## 2D 場景與星望市全景（v1.27.0）

- 新繪水彩城市原畫包含全部 26 個地點，每棟建築對應可探索的熱區，機場保留進度條件。
- 桌機移入建築才顯示介紹與當日線索；點擊固定預覽，再選日期確認前往。觸控裝置採點選預覽。
- 地圖可拖曳、搜尋、放大、縮小與全覽；不再透過街區列表換頁。自由活動當天也使用同一張城市圖。
- 房間中的窗外、平板、手機、文件、筆記與書刊各自連到對應玩法；底部保留自訂快捷列與 18 個功能圖示選單。
- 課程、公司打工、工作卡及創作類型加入場地圖片；人物互動置於資料之前，能力、週報與社群說明按需展開。
- 查看、滑動、試讀和預覽不推進日期、不消耗資源、不提前解鎖；替換重要預約仍需確認並可復原。
- 保留紙娃娃、原人物與原房間美術，沿用既有存檔。新地圖及樣式納入離線快取。

## 工作機會循序開放（v1.26.0）

- 新人直接可接市民服務台公開招募的活動零工；公開試鏡與街頭演出先到電視台／河濱公園了解登記規則。
- 電視台棚務助理、影業片場場務、唱片製作行政、廣告拍攝助理四種公司打工，首次實際到訪後出現在行程表。
- 排入打工不給經驗或薪資；完成當天工作才領日薪、獲得少量能力成長，並累積各公司獨立經驗。
- 同公司三次打工後，建立持續提供徵選資訊的窗口並接觸兩星機會；能力、訓練及試鏡資格仍需達標。
- 兩份相關作品也能建立該產業的工作聯絡；熟識且信任的人脈、有效經紀公司的實際推薦及成熟履歷帶來其他機會。
- 高階正式工作仍依作品經驗逐步開放；初始空白工作紀錄不再繞過接觸門檻。已投遞、試鏡或簽約的舊進度保留。

## 目前版本重點

### 五年不是 260 次重複排程

五年改成明確章節：

1. **Year 1｜活下來**：站穩新人期，能力、錢與第一份履歷都不足。
2. **Year 2｜我是誰**：開始建立清楚的職涯方向。
3. **Year 3｜位置有限**：同期、NPC、榜單、獎季與資源競爭變得具體。
4. **Year 4｜選擇有代價**：商業、作品、健康、關係與自主權互相拉扯。
5. **Year 5｜留下什麼**：代表作與長期關係收束成最後的五年答案。

每年都有可見目標與壓力；每 13 週會再次提醒玩家目前的安排是否仍朝章節目標前進。

Year 2～5 也有真正改變玩法的長期決策：第二年承諾半年主軸，第三年選擇競爭方式，第四年決定願意拿什麼交換成功，第五年則決定最後要留下作品、關係或制度。選項會持續改變聲望、收入、健康、人物收益與結局，而不是只顯示一句結果。

### 75 份工作改成 A／B／C 深度

通告總數仍維持 **75 份**，不靠擴充數量解決重複感。

- **35 份 C 級基礎工作**：保留完整流程，其中 J001～J010 已有專屬現場矛盾、關鍵場次與市場回聲，其餘以類型骨架支撐一般職涯節奏。
- **25 份 B 級特色工作（J036～J060）**：每份至少有兩個真正專屬的製作事件，以及該作品自己的公開後回聲。
- **15 份 A 級旗艦工作（J061～J075）**：每份都有專屬開工、危機、關鍵選擇、完成與長尾，會成為代表作候選與中後期主要戲劇內容。

試鏡選擇仍會帶回製作與成品；正式工作必須依指定工作日排入行事曆，期限內未完成會違約。

### 世界會記得玩家做過什麼

重大作品與違約不再只停在一次結算：

- 先寫入跨週 `worldEchoes`。
- 到期後轉成娛樂圈週報中的長尾回聲。
- 同一件事可再進入可見事件、星光社群或人物訊息。
- 已播放回聲會去重，不會無限洗版。

因此玩家幾週前的選擇，可能在後續宣傳、網路討論、合作信任或人物反應裡再次出現。

### NPC 有自己的職涯

目前仍是 **10 位主要 NPC**，不橫向增加人數。每位都有背景、公開形象、私下面貌、動機、恐懼、價值觀、人物弧線與三章人物主線；七類相處行為皆有角色專屬事件。

除了玩家主動互動外，NPC 也會自行：

- 接新作品、遇到低潮或失利。
- 因理念與市場做取捨。
- 休息、轉型或累積新的職涯位置。
- 透過週報／社群被玩家看見。

如果玩家已經認識該 NPC，部分近況還會自然進入私人訊息；**尚未相遇的人不會因此憑空進通訊錄**。

十位 NPC 各有五段新增跨年章節，現在會以多幕場景呈現，選項包含事前代價說明並各自排入不同的數週後回收。NPC 也會主動發出私人邀約；接受、明確拒絕或改期都有不同記憶。五組雙 NPC 場景會讓玩家在兩段關係之間做不能同時討好的選擇。

平板底部的「星途時間線」會把人物訊息、私人邀約、作品、重大事件與永久方針依週次集中顯示，減少在多個 App 間尋找後果的負擔。

平板新增「星途影像館」：已走過的章節 CG 會解鎖，並可直接重讀多幕故事；目前整合 **102 張場景／CG**。求婚、婚禮、分手、續約、旗艦作品第三解與「完整人生」結局都有專屬畫面；十位主要 NPC 均有關係路線代表 CG，多周目沈霧棠線也收錄影展與檔案室畫面。

沈霧棠的二周目隱藏線由三幕擴成八章：相遇、記憶重疊、矛盾、影展、刪除檔案、同意界線、重新選擇與首映終章。它不再把「命定」當答案；第三周目或高洞察玩家還能選擇共同寫出第三個版本。

### 戀愛是關係，不是「好感 +7」

感情狀態支援：`none → interested → ambiguous → dating → committed → engaged → married`，並包含拒絕、分手、復合、地下戀、公開戀情與唯一伴侶限制。

不同階段現在有專屬日常／訊息語氣。正式交往後，關係會透過報備、忙碌時的短訊、熟悉彼此工作壓力、訂婚與婚後生活被玩家感受到，而不是只看數字。

### 經紀人是真正的合作對象

四間公司各有固定經紀人，不只提供邀約量與試鏡 bonus。每位經紀人都有自己的工作哲學，並具備：

- 保守判斷
- 進取判斷
- 危機處理
- 續約立場

既有互動可以選擇傾聽、堅持或折衷，會改變 trust／stress／rapport；本週的經紀人判斷也會顯示在首頁與娛樂圈週報。

### 成就是跨周目的生涯收藏

成就由 15 項擴充為 **81 項**，涵蓋 19 種結局原型、8 項隱藏特質、8 項聲望、4 種經紀人立場、永久方針、旗艦作品、續約、戀愛與多周目隱藏線。解鎖紀錄會保存周目與週次，開始新一輪時不會被清空；成就 App 可依類別篩選並顯示生涯完成率。

少數最高張力節點另有條件式特殊選項：A 級旗艦案可提出「第三份答案」、深厚戀情可選非典型求婚／私人婚禮，第五年則可在能力與作品量足夠時選擇「完整人生」。一般事件仍維持精簡選項，不讓每個節點都膨脹。

## 核心系統

### 角色與能力

- 自訂姓名、性別／稱呼。
- 四款可選玩家立繪，男女各兩款；非二元／自訂稱呼可自由選外型。
- 五套場合服裝：新人私服、練習服、試鏡造型、舞台造型、典禮禮服。
- 21 項公開能力；初始值可無限重骰。
- 8 項隱藏特質與 8 項娛樂圈聲望。
- 服裝加成會實際進入資格、試鏡、面談與作品品質，但不永久灌入基礎值。

隱藏特質與聲望不直接揭露精確骰值；達到明顯程度後，玩家會從世界反應知道，例如「合作方開始更信任你的判斷」或「普通發言也更容易被放大」。

### 行程與健康

每週七格，每日一個主要安排。行程包含訓練、自由活動、試鏡、正式工作、人物活動、創作、社群與經紀人／公司面談等。

行程頁目前會：

- 顯示進行中通告剩餘場次與指定工作日。
- 預警「期限 × 本週可用工作日」衝突。
- 用「大致穩定／小幅上升／明顯上升／高風險」呈現疲勞趨勢。
- 保留一鍵範本與「依期限安排正式通告」。
- 不顯示精確成功骰值。

疲勞、體力、健康與心情會共同影響訓練、試鏡、面談、探索與正式工作品質；過勞可能強制住院，極端狀況可進入過勞結局。

### 經紀公司

目前四間公司：星光藝能、映界文化、澄音娛樂、浪潮媒體，各自偏向不同職涯方向。

支援：

- 資格比對與投遞。
- 面談排入行程並在當天結算。
- 面談選擇與文字勝算提示，不外露精確機率。
- 正式合約、抽成與公司新人任務。
- 經紀人推薦工作。
- 合約最後八週續約談判與改善條件。
- 到期後恢復自由藝人，可重新投遞。

### 作品、獎項與創作

- 正式通告完成後建立作品履歷，記錄類型、星級、品質與合作資訊。
- 三星以上且品質達標才進入獎季候選；不會殺青瞬間直接頒獎。
- 年度典禮週才進行入圍／得獎判定並呈現典禮事件。
- 創作工作室提供三類企劃 × 三種創作方向。
- 可選公司共同製作、販售企劃權、自主製作／發行。
- 成品有品質、星級、市場分數與後續收益／回聲。

### 星望市地圖

地圖維持 **26 個地點**，涵蓋娛樂產業、訓練、靈感、生活、休閒、健康與交通。

本階段不再擴點，改為深化同一地點：

- 週末／平日氣氛不同。
- 疲勞高時，訓練地點會直接提示狀態風險。
- 產業據點會顯示工作櫃台與徵選線索。
- 已認識 NPC 若合理出現在該處工作，可出現「熟悉保母車／工作團隊」等線索。
- 陌生 NPC 不會被地圖提前劇透。

國際機場在第二年且具備知名度與作品履歷後開放海外影展、音樂節與公開徵選。

### 社群、論壇與娛樂圈週報

- 星光社群可發文、按讚、回覆已認識 NPC。
- 星談論壇會依玩家近期工作、人氣與爭議形成話題。
- 娛樂圈週報集中顯示市場、作品生命週期、NPC 職涯、競爭者、品牌、經紀人壓力與世界回聲。
- 作品長尾、履約回聲、NPC 近況與世界反應也會進入社群，讓後台變化真正進到玩家眼前。

## 首頁與操作

房間仍是主要場景，平板作為功能中心。首頁資訊收斂為三層：

1. **現在最急**：健康／疲勞、迫近工作期限或待處理事件。
2. **有人在找你**：人物未讀訊息或經紀人最新判斷。
3. **本章目標**：目前年度主題、目標與壓力。

完整市場、作品與世界資訊往娛樂圈週報收，不把首頁做成資訊牆。

平板首頁另外整合成 **17 個 App 的 App Library**：行程、時間線、影像館、能力、人物、紀錄、娛樂週報、地圖、工作信箱、創作室、社群、論壇、衣櫃、經紀公司、成就、存檔與設定改用低飽和、紙感細線的文青圖示。「人物」以分頁整合訊息、人際關係與人物檔案，不再放兩個用途重疊的 App。玩家可直接從 App Library 編輯下方六格 Dock，自由挑選與排列常用 App；選擇會寫入存檔並延續到下一周目，未讀訊息、進行中工作與解鎖收藏仍會顯示角標。

介面已統一中文字型規範並取消非語意斜體；工作與聯絡人長清單提供搜尋／排序、未讀狀態，關閉再開啟 App 會回到原捲動位置。設定頁可分別調整環境音樂與操作音效。

## 存檔、離線與多周目

目前 save schema 為 **v16**。

- 自動存檔。
- 五個手動槽。
- 讀檔前備份。
- JSON 匯出／匯入。
- 舊版逐版 migration＋`hydrateState()` 正規化。

## 技術架構

專案採純瀏覽器 ES Modules：

```text
src/data/*   → 內容與設定
src/core/*   → state、存讀檔、RNG、工具
src/logic/*  → 規則與狀態變化
src/views/*  → state → HTML
src/bind/*   → UI 事件
render.js    → 唯一重繪入口
main.js      → 開機入口
```

完整不變量、每週世界推進順序與深化層說明見 [`ARCHITECTURE.md`](./ARCHITECTURE.md)。

1～16 垂直深化完成定義見 [`DEEPENING-1-16.md`](./DEEPENING-1-16.md)。

## 本機執行與測試

```bash
npm install
npm run validate
npm test
npm run test:e2e
npm run build
```

也可使用：

```bash
npm run check
```

`npm run build` 會產生只含遊戲 runtime 與素材的 `dist/`；GitHub Pages 不直接發布整個 repository。

`npm run validate` 目前會依序執行：

1. 核心內容交叉引用驗證。
2. 擴充內容驗證。
3. `validate-deepening.mjs`：固定檢查 **75 工作／15 A／25 B／35 C／5 年章節／10 NPC 八章主線／專屬戀愛聲音／世界反應**。

九分深化的十項驗收與 260 週人工式路徑稽核見 [`DEPTH-V2.md`](./DEPTH-V2.md)。

`npm test` 執行核心規則與深化回歸測試；Playwright 以 Chromium 驗證桌機／手機關鍵流程。
GitHub Actions 會安裝 Chromium 與系統相依套件，並在推送 main 或建立 PR 時執行完整 `check` 與桌機／手機 E2E。

## 內容維護原則

- 不用更多一次性隨機事件掩蓋重複感。
- 不為了「看起來很多」先增加 NPC、地點與通告總數。
- 新事件優先設計可被後續引用的結果。
- 所有重要結果要回答：**玩家之後會在哪裡再次感受到這件事？**
- 資料寫在 `data/`、規則寫在 `logic/`、畫面只讀 state。
- 新亂數一律走 `core/rng.js`，維持可重現 bug。
- 新增重要狀態必須有 validator 或測試防線。
